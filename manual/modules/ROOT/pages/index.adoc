= Navico Autopilot

Controls a Navico autopilot computer, B&G or Simrad, directly over
NMEA 2000.

image::panel.png[Autopilot panel]

== Links

* Source and test builds: https://github.com/xanderburchartz/navico_autopilot_pi[GitHub]
* Test reports and issues: https://github.com/xanderburchartz/navico_autopilot_pi/issues[GitHub issues]
* Installation: xref:opencpn-plugins:misc:plugin-install.adoc[Plugin Download, Install and Enable]

== What it does

* Switches the pilot to Standby, Auto (heading hold), Wind, Nav or No Drift.
* Changes the course by -10, -1, +1 or +10 degrees. In Wind mode these
  buttons change the wind angle to hold.
* Shows the pilot mode, the heading and the target heading or wind angle.

It works with the autopilot computers that take commands from a B&G or
Simrad pilot keypad over NMEA 2000: NAC-1, NAC-2, NAC-3, AC12 and AC42.
So far it has been used with a B&G NAC-3.

== Requirements

* OpenCPN 5.14 or later.
* An NMEA 2000 connection in OpenCPN that can transmit, for example a
  Yacht Devices or Actisense gateway on the network, an Actisense NGT-1 or
  SocketCAN on Linux. The plugin has no CAN driver of its own.

OpenCPN 5.12 loses every second command on network gateways (Yacht Devices
RAW, Actisense RAW ASCII), so the plugin needs 5.14 for those.

== Setting up

. Make sure the NMEA 2000 connection exists in Options, Connections, with
  output enabled.
. Enable the plugin in Options, Plugins.
. Open its Preferences and choose the NMEA 2000 connection.
. The autopilot and the rudder sensor are found automatically; the first
  entry of each list names the one in use. With more than one candidate the
  plugin takes the most likely one (a Navico pilot computer, a rudder
  feedback unit that is not "virtual"). Pick another entry to overrule it.
  Opening the settings asks the devices once for their name and model, so
  give the lists a few seconds to fill.

== Using it

The steering wheel button in the toolbar shows and hides the panel. The
panel can float or be docked, like other OpenCPN panels.

The display follows a Navico pilot controller: the heading arc at the top,
with the set heading (or the bearing to the waypoint) as a triangle, red to
port and green to starboard; the mode on the left; two values on the right;
the rudder angle at the bottom.

[cols="1,2,2"]
|===
|Mode |Upper value |Lower value

|Standby |Heading |Boat speed
|NFU (standby, button held) |Rudder angle |Boat speed
|Auto, No Drift |Set heading |Boat speed
|Nav |Bearing to the waypoint |Distance to the waypoint
|Wind |Apparent wind angle |Set wind angle
|===

Headings are shown in the reference the pilot uses, true or magnetic. The
colours follow OpenCPN's day, dusk and night schemes; at night everything is
dim red.

Boat speed is the speed over ground from OpenCPN, or the speed through the
water from the log; choose it in the settings.

STBY works whenever a pilot is selected, also without recent data. The
other mode buttons need recent data from the pilot. The course buttons work
in Auto, Wind and No Drift.

In standby the course buttons work as on a Triton2: non-follow-up (NFU).
The rudder moves as long as you hold a button, -1 and -10 to port, +1 and
+10 to starboard, and stops when you let go. The plugin repeats the command every
half second while held and sends stop three times on release; it also stops
when the panel closes or OpenCPN loses focus.

=== Tack and gybe

In Wind mode *TACK* opens a window with the heading now, the expected
heading after the manoeuvre and the new wind angle; with the wind further
aft than 90 degrees it is a gybe. *Tack* or *Gybe* sends the command, the
pilot chooses the side. The window closes by itself after 10 seconds.

=== Navigation

NAV needs a confirmation, as on a pilot controller or MFD. After NAV the
plugin opens a window with the bearing the pilot will turn to and a
countdown: the pilot waits 10 seconds. *Confirm* starts navigation,
*Cancel* leaves the pilot as it was. Confirming on another controller also
works; the window then closes by itself.

The pilot follows the route or waypoint of the active navigation source on
the bus, for example the plotter or OpenCPN. Without valid navigation data
the pilot does not change to NAV and reports "Navigation data missing".

=== Autopilot settings

The gear at the top right of the panel opens the settings the pilot computer
keeps itself. The plugin asks the pilot for each value when the window
opens, one at a time; a value that stays at `...` got no answer, *Read
again* asks once more. Not every pilot answers every request on the first
try.

The window first shows what a Triton2 shows under its autopilot menus:
*Sailing* (tack angle and tack time) and the steering profiles *Low speed*
and *High speed*, each with turn rate, rudder gain, counter rudder,
autotrim, rudder limit, off heading limit, track response, track approach
angle and course change confirm angle. Autotune adjusts the profile in use.

The installation settings (boat, drive, rudder) are hidden: press
*Installation* three times within three seconds to show them. Boat type,
drive voltage, drive engage and the rudder calibration are shown but cannot
be changed here: a wrong value there can harm the drive or belongs to the
commissioning steps on the pilot controller. The control method is not in
the list.

*Change* next to a value, or a value in the profile table, asks for the new
value within a range, asks for confirmation and then sends it. The pilot
answers with the value it took, which can be rounded to its own resolution;
the window shows that answer.

==== Snapshots

Before the first change in the window the plugin stores the settings as
they are, a snapshot. *Snapshots...* takes one by hand or lists the stored
ones. Choosing one shows which values differ from now; after a confirmation
the plugin sends those back one at a time, after first taking a snapshot of
the current settings. Only settings the plugin may change are sent back.
The snapshots are text files in OpenCPN's data folder, under
`plugins/navico_autopilot_pi/snapshots`.

Apart from NFU, each button press sends one command, with no heartbeat. Every
command is written to the OpenCPN log with its bytes, on lines starting with
`navico_autopilot_pi:`.

== Messages

No autopilot found::
No pilot mode reports seen on the chosen connection. Check that the
connection receives NMEA 2000 data and that the pilot computer is on.
Choose the NMEA 2000 connection in the plugin settings::
OpenCPN has no NMEA 2000 connection, or more than one and none is chosen.
No reply from the autopilot. Is transmitting enabled on the gateway?::
The pilot did not echo the command within 1.5 seconds. Check that the
connection has output enabled.
The autopilot did not change mode::
The pilot echoed the command but did not follow it within 3 seconds, for
example NAV without navigation data.
Alarm: ...::
An alarm the pilot reports, with its own text, as long as it is active.
The autopilot did not answer. It may accept settings requests only from its own displays.::
None of the settings requests got an answer. The NAC-3 answers through a
Yacht Devices gateway; other pilots or gateways may not.
No answer from the autopilot: the setting may not have changed. Read again to check.::
After *Change* the pilot did not answer within 3 seconds.

== How it works

The plugin sends PGN 130850, the proprietary command a B&G or Simrad pilot
keypad uses, and reads the pilot's mode, echoes and alarms, the rudder
angle, the wind and the navigation data. The byte layouts are in the
https://github.com/xanderburchartz/navico_autopilot_pi#protocol[README].
